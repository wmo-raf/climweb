# Writing accessible content

ClimWeb's pages are built to be accessible, but what you publish matters just as much. These habits make your content usable by people who use screen readers, keyboards, magnification or captions.

## Images

### Image descriptions

When you upload an image, fill in its **Description**. ClimWeb uses it as the image's alt text: the text a screen reader reads out, and what shows if the image doesn't load.

- **Say what the image shows and why it's there**, in one or two sentences: "Rainfall anomaly map for March 2026: wetter than normal across the western highlands."
- **Don't start with "Image of" or "Picture of".** Screen readers already say "image".
- **Don't repeat nearby text.** If the caption or heading already says it, keep the description short.
- **Don't use the file name.** "IMG_2041.jpg" or "banner" tells a listener nothing. Without a description, ClimWeb falls back to the image title, which is often the file name.

### Alt text and decorative images in content blocks

Some content blocks (title/text/image sections, feature figures, collapsible sections, news galleries and product maps) show two extra options under the image:

- **Alt text**: alt text for this particular use of the image, which overrides the description. Use it when the same image means something different on different pages.
- **Image is decorative**: tick this when the image adds nothing a listener would miss, for example a background photo or an icon next to a heading that says the same thing. Screen readers then skip it.

Both are optional. If you leave them blank, ClimWeb uses the image's description, then a sensible fallback such as the block heading.

### Maps, charts and bulletins as images

- A map or chart uploaded as an image needs a description of **what it shows**, not just its title: the key finding, the area and the period.
- Don't publish text only as an image, such as a bulletin saved as a picture. Also publish it as page text or as an accessible PDF, so it can be read aloud, zoomed and translated.

## Headings

- Use the **heading styles** in the editor (Heading 2, Heading 3), not bold text. Screen reader users jump between headings to scan a page.
- Keep them in order: a Heading 3 goes under a Heading 2, not straight after the page title.

## Links

- Link text should make sense on its own: "Download the March 2026 seasonal outlook (PDF, 2 MB)", not "click here" or "read more".
- Say when a link opens a file, and its type and size.

## Colour

- Never use colour alone to carry meaning. "Areas in red" means nothing to someone who can't see red. Name the areas, or use labels and patterns as well.
- Under **Settings → Themes**, ClimWeb warns you if a brand colour you choose is too light to read on white. Pick a darker shade if you see that warning.

## Video and audio

- Turn on **captions** for YouTube videos, and check that automatic captions are correct.
- Give audio (podcasts, radio bulletins) a **transcript**, as page text or a linked document.
- Don't rely on sound alone for important information, such as a warning only spoken in a video.

## Documents

- Prefer publishing information as a web page. Pages are easier to read on phones and with screen readers than PDFs.
- If you publish a PDF, export it from Word or similar with **headings and alt text included** ("tagged PDF"). Scanned documents are images and can't be read by screen readers.

## Tables

- Use tables for data only, not for layout, and give each one a header row.

## Forms (Flexible forms)

- Give every field a clear **label**; the placeholder text inside a field isn't a label.
- Use **help text** for format hints: "Date as DD/MM/YYYY".
- Name fields plainly ("Email", "Phone number", "Organisation"). ClimWeb recognises these names and lets browsers fill them in automatically.
